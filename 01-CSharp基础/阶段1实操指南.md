## 新手最容易踩的 7 个坑

1. **中文标点**：`；`、`，`、`（）`、`“”` 全角符号都会让代码报错。写代码时切英文输入法。
2. **每句末尾要有英文分号 `;`**，C# 大小写敏感：`Console` 不是 `console`，`String` 和 `string` 不是一回事（后者是小写别名，日常都用小写）。
3. `int.Parse("abc")` 会让程序**崩溃**——这是正常的，第 12 课讲怎么防。看到红色报错别慌。
4. `Console.ReadLine()` 可能返回空值，统一写成 `string input = Console.ReadLine() ?? "";`（`?? ""` 意思是“如果为空就用空字符串”）。
5. **怎么读报错**：先看最后一行英文和它上面的行号。`CS` 开头的错误（如 CS1002）是编译错误，程序根本没跑；`Unhandled exception`（未处理异常）是运行到那一步才崩的。把报错信息连同代码发给我也行。
6. **`.gitignore` 只排除编译产物和编辑器临时文件**（bin、obj、.vs 等），**永远不要把自己的 `.cs` 源码加进去**——被忽略的文件 Git 当它不存在，`git status` 还显示"干净"，代码会一直推不上 GitHub 且很难发现。
7. **一个项目只能有一个含顶级语句的文件**：别把 `Program.cs` 的备份留在项目文件夹里。像 `Program - 复制.cs` 这种副本如果也含 `Console.WriteLine`，会报 **CS8802**（只有一个编译单元可具有顶级语句）。备份请改名为 `.cs~`（`.gitignore` 已忽略 `*~`）或移出项目文件夹。

### 第 2 课 运算符与类型转换（对应打卡：运算符）

```csharp
int a = 7;
int b = 2;

Console.WriteLine(a + b);   // 9
Console.WriteLine(a - b);   // 5
Console.WriteLine(a * b);   // 14
Console.WriteLine(a / b);   // 3  ← 整数除法，小数被直接丢掉
Console.WriteLine(a % b);   // 1  ← 取余数
Console.WriteLine(7.0 / 2); // 3.5 ← 有一个是小数，就按小数算

bool isGreater = a > b;             // true
bool both = isGreater && b > 1;     // true，&& = 并且
Console.WriteLine(both);
```

类型转换：

```csharp
double d = 3.9;
int truncated = (int)d;               // 3  ← 强制转换：直接截断小数（向零方向）
int rounded = Convert.ToInt32(d);     // 4  ← 就近取整。注意：遇到 .5 取偶数（银行家舍入），不是严格四舍五入
Console.WriteLine(truncated);
Console.WriteLine(rounded);

string s = "123";
int n = int.Parse(s);         // 字符串 → 整数
Console.WriteLine(n + 1);     // 124
```

### 第 4 课 循环（对应打卡：流程控制）

```csharp
// for：打印 1 到 5
for (int i = 1; i <= 5; i++)
{
    Console.WriteLine(i);
}

// 累加器：求 1 到 100 的和
int sum = 0;                       // 必须在循环外面声明，否则每轮都会被清零
for (int i = 1; i <= 100; i++)
{
    sum += i;                      // 等价于 sum = sum + i;
}
Console.WriteLine($"1 到 100 的和 = {sum}");   // 5050

// while：数到 10
int count = 1;
while (count <= 10)
{
    count++;                       // 忘了这句就会死循环
}
Console.WriteLine($"最后 count = {count}");
```

嵌套循环——九九乘法表：

```csharp
for (int i = 1; i <= 9; i++)
{
    for (int j = 1; j <= i; j++)
    {
        Console.Write($"{j}x{i}={i * j}\t");   // \t 是制表符，对齐用
    }
    Console.WriteLine();   // 每行结束换行
}
```

`break` / `continue`（猜数字练习里会用到）：

```csharp
for (int i = 1; i <= 10; i++)
{
    if (i == 4) continue;   // 跳过本轮剩余代码，直接进入下一轮
    if (i == 7) break;      // 整个循环立刻结束
    Console.Write($"{i} "); // 输出 1 2 3 5 6
}
```

> 嵌套循环里的 `break` 只跳出**当前这一层**，不会一次跳出两层。

### 第 5 课 方法（对应打卡：方法）

C# 程序里重复的逻辑要抽成**方法**。顶级语句写法里，方法定义**习惯上**写在文件末尾、调用写在前面（实测方法定义放最前、中间、交错都合法；真正的硬规矩是：**类型声明必须放在所有语句之后**，报错 CS8803，第 8 课会用到）：

```csharp
int total = Add(3, 5);
Console.WriteLine(total);          // 8

PrintMenu("记账本");

double myBmi = CalcBmi(70, 1.75);
Console.WriteLine($"BMI = {myBmi:F1}");   // 22.9

int Add(int x, int y)
{
    return x + y;
}

void PrintMenu(string title)
{
    Console.WriteLine($"== {title} ==");
    Console.WriteLine("1. 收入  2. 支出  0. 退出");
}

double CalcBmi(double weightKg, double heightM)
{
    return weightKg / (heightM * heightM);
}
```

- `void` 表示“不返回结果”
- 方法里声明的变量，外面看不见（**作用域**）；反过来，参数名可以和外面的变量同名，参数是方法自己的一份，跟外面的同名变量无关

方法**重载**：同一个名字、参数不同，算不同的方法。`Console.WriteLine` 自带十几个重载，所以打印数字、文本、小数都行：

```csharp
Console.WriteLine(123);      // 重载之一：打印 int
Console.WriteLine("123");    // 重载之一：打印 string
```

> 注意：**顶级语句里的方法不能自己写重载**——再定义一个 `double Add(double a, double b)` 会报 CS0128（同名冲突）。重载要等第 8 课把方法写进类里才能上手。

### 第 6 课 数组、List、Dictionary（对应打卡：数组、List、Dictionary）

```csharp
// 数组：长度固定
int[] scores = { 90, 75, 88, 60 };
Console.WriteLine(scores.Length);   // 4
Console.WriteLine(scores[0]);       // 90，下标从 0 开始

// List：长度可变，最常用
var names = new List<string> { "张三", "李四" };
names.Add("王五");
names.Remove("李四");
Console.WriteLine(names.Count);     // 2

foreach (string item in names)      // 循环变量别和外层已声明的变量重名（CS0136）
{
    Console.WriteLine(item);
}

// Dictionary：键 → 值 的查找表
var prices = new Dictionary<string, int>
{
    ["苹果"] = 5,
    ["香蕉"] = 3
};
prices["葡萄"] = 8;
Console.WriteLine(prices["香蕉"]);   // 3

foreach (var kv in prices)
{
    Console.WriteLine($"{kv.Key} = {kv.Value} 元");
}
```

三者怎么选：

| 集合 | 特点 | 什么时候用 |
|---|---|---|
| 数组 `int[]` | 长度创建后不能变 | 数据个数固定、追求简单 |
| `List<T>` | 可随时增删、`Count` 查数量 | **默认选择**，记账本就用它 |
| `Dictionary<K,V>` | 按键快速查值 | 统计、查表（如按分类汇总） |

2. List 添加 3 个水果再删掉 1 个，打印剩余
3. 用 Dictionary 存 3 门课成绩，遍历打印“科目：分数”
4. 在 `笔记/` 里写三行：数组和 List 的区别

### 第 7 课 字符串处理（对应打卡：字符串处理）

```csharp
string text = "  Hello, C# World  ";

Console.WriteLine(text.Trim());             // 去掉首尾空格：Hello, C# World
Console.WriteLine(text.Trim().ToUpper());   // 转大写：HELLO, C# WORLD
Console.WriteLine(text.Contains("C#"));     // True
Console.WriteLine(text.Replace("World", ".NET"));  // "  Hello, C# .NET  "（首尾空格还在，Replace 不动别的地方）
Console.WriteLine(text.Length);             // 19（含空格）

string sentence = "苹果 香蕉 葡萄";
string[] words = sentence.Split(' ');       // 按空格拆成数组
Console.WriteLine(words.Length);            // 3
Console.WriteLine(words[1]);                // 香蕉

string userName = "小明";   // 别用 name：第 1 课已经声明过 string name，会报 CS0128
Console.WriteLine($"你好，{userName}！今年 {DateTime.Now.Year} 年");
```

和 JS 对照：`.Trim()`/`.ToUpper()`/`.Contains()` 就是 JS 的 `trim()`/`toUpperCase()`/`includes()`，只是 C# 方法名首字母大写。有个真区别：C# 的 `Replace` **替换全部**出现的地方，JS 的 `replace("a","b")` 只替换**第一个**（要全部得用 `replaceAll`）。

注意 `text.Length` 是**属性**，不能写 `text.Length()`，报 CS1955（不可调用的成员）。

## 第 3 周：面向对象

### 第 8 课 类与对象、构造函数、属性（对应打卡：类、属性、构造函数）

**类 = 图纸，对象 = 按图纸造出来的具体东西。** 一个类可以造无数个对象。

JS 里你已经写过几乎一样的骨架：

```js
class Book {
  constructor(title, author, price) {
    this.title = title;
    this.author = author;
    this.price = price;
  }
  getInfo() {
    return `${this.title} / ${this.author} / ${this.price}`;
  }
}
const book1 = new Book("C# 入门", "张三", 59.9);
```

C# 的骨架一样，但有三个硬性区别：成员必须先声明类型；构造函数名必须跟类名相同（不写 `constructor`）；类成员默认是私有的，想让外面访问必须写 `public`。

本节代码（追加在第七节 `end` 之后；**类必须放在文件最末尾**）：

```csharp
Console.WriteLine($"第八节 start");

var book1 = new Book("C# 入门", "张三", 59.9m);
var book2 = new Book("ASP.NET Core 实战", "李四", 89m);
Console.WriteLine(book1.GetInfo());   // C# 入门 / 张三 / 59.90 元
Console.WriteLine(book2.GetInfo());   // ASP.NET Core 实战 / 李四 / 89.00 元

book1.Price = 49.9m;                  // 属性可写：改价格
Console.WriteLine($"改价后：{book1.GetInfo()}");

Book bookAlias = book1;               // 两个变量指向同一个对象
bookAlias.Price = 39.9m;
Console.WriteLine($"别名改价后：{book1.GetInfo()}");

var book3 = new Book("没有作者的书");  // 匹配重载的构造函数
Console.WriteLine(book3.GetInfo());   // 没有作者的书 / 佚名 / 0.00 元

Console.WriteLine($"第八节 end");

public class Book
{
    public string Title { get; set; }
    public string Author { get; set; }
    public decimal Price { get; set; }

    public Book(string title, string author, decimal price)
    {
        Title = title;
        Author = author;
        Price = price;
    }

    public Book(string title)
    {
        Title = title;
        Author = "佚名";
        Price = 0m;
    }

    public string GetInfo()
    {
        return $"{Title} / {Author} / {Price:F2} 元";
    }
}
```

运行结果应该和下面完全一致：

```text
第八节 start
C# 入门 / 张三 / 59.90 元
ASP.NET Core 实战 / 李四 / 89.00 元
改价后：C# 入门 / 张三 / 49.90 元
别名改价后：C# 入门 / 张三 / 39.90 元
没有作者的书 / 佚名 / 0.00 元
第八节 end
```

逐块拆开看：

- `public class Book`：声明一个类型，类名习惯用大驼峰。
- `public string Title { get; set; }`：**自动属性**。`get` 表示外面能读，`set` 表示外面能写。它用起来像字段，实际是“带方法的成员”，编译器在背后自动生成一个隐藏字段来存值。第 9 课封装会把隐藏字段写出来。
- `public Book(string title, string author, decimal price)`：**构造函数**。名字必须和类名一模一样，而且不写返回类型（连 `void` 都不写）。`new Book(...)` 时自动执行，负责把对象初始化好。
- `public string GetInfo()`：普通方法。和之前写的本地函数一样，只是多了 `public`。
- `59.9m` 的 `m`：`decimal` 字面量后缀（第 1 课提过）；漏了会报 CS1503（无法从 double 转换为 decimal）。
- 构造函数里写 `Title = title;` 就够了，不用像 JS 那样写 `this.Title`：在类的实例成员内部，裸名字 `Title` 会被编译器当成 `this.Title`。如果参数也叫 `Title`，就必须写 `this.Title = Title;`——写成 `Title = Title;` 只是把参数赋给自己，编译器会警告 CS1717，属性仍然是 null。

**对象变量存的是引用。** `Book bookAlias = book1;` 没有复制对象，只是多了一个指向同一对象的名字，所以改 `bookAlias.Price`，`book1` 看到的也变了。JS 的对象、数组也是这个行为；`int`、`double` 这类值类型则是复制一份。

**构造函数可以重载。** 第 5 课说过顶级语句里的局部函数不能重载（CS0128）；写进类里就可以了——`Book(string, string, decimal)` 和 `Book(string)` 同名不同参数，`new Book("没有作者的书")` 会自动匹配只传一个参数的那个。普通方法同理，`GetInfo()` 再写一个 `GetInfo(bool withPrice)` 也算重载。

> **位置规矩（追加式写法必看）**：顶级语句（你写的 `Console.WriteLine` 等）必须全部排在类声明**之前**，否则报 **CS8803**。所以第 9 课开始，新代码要插在 `public class Book` **之前**，直接追加到文件末尾会编译失败。类里面也不能直接写语句，只能写成员（属性、构造函数、方法）。

常见错误对照（本机实测）：

| 错误写法 | 报错 |
|---|---|
| 把 `public class Book` 放在语句前面 | CS8803：顶级语句必须位于命名空间和类型声明之前 |
| `var b = Book("x", "y", 1m);` 忘了 `new` | CS1955：不可调用的成员“Book”不能像方法一样使用 |

### 第 9 课 封装：private 字段 + 只读属性 + 校验（对应打卡：类、属性、构造函数）

**封装 = 把数据藏起来，只让方法按规矩改它。** 第 8 课的对象谁都能改（连 `book1.Price = -100` 都行），本节要把这种"随便改"挡住。

JS 里你已经见过同样的思路（`#` 私有字段 + 只读 getter）：

```js
class Account {
  #balance = 0;                              // 外面碰不到
  get balance() { return this.#balance; }    // 只能读
  deposit(amount) { if (amount <= 0) return; this.#balance += amount; }
  withdraw(amount) {
    if (amount <= 0 || amount > this.#balance) return false;
    this.#balance -= amount; return true;
  }
}
```

C# 的写法一一对应：`private decimal _balance;` ≈ `#balance`，`public decimal Balance { get { ... } }` ≈ 只读 getter。区别是 C# 的 `private` 指"本类内部可访问"（子类也不行），JS 的 `#` 更严格（连类外反射都拿不到）——本课只要抓住核心：**数据字段藏起来，外面只能通过属性和方法访问。**

本节代码（插在第八节 `end` 之后、`public class Person` **之前**；`Account` 类加在文件末尾 `Book` 后面）：

```csharp
Console.WriteLine($"第九节 start");

var account = new Account();
account.Deposit(100);
Console.WriteLine(account.Balance);   // 100

bool ok = account.Withdraw(30);
Console.WriteLine(ok);                // True
Console.WriteLine(account.Balance);   // 70

bool ok2 = account.Withdraw(1000);
Console.WriteLine(ok2);               // False：余额不足
Console.WriteLine(account.Balance);   // 70：钱没动

account.Deposit(-50);                 // 非法金额，直接忽略
Console.WriteLine(account.Balance);   // 70

Console.WriteLine($"第九节 end");

public class Account
{
    private decimal _balance;             // private：只有类内部能碰

    public decimal Balance
    {
        get { return _balance; }          // 只读属性：外面能看，不能直接改
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
        {
            return;                       // 不合法就忽略
        }
        _balance += amount;
    }

    public bool Withdraw(decimal amount)
    {
        if (amount <= 0 || amount > _balance)
        {
            return false;
        }
        _balance -= amount;
        return true;
    }
}
```

运行结果应该和下面完全一致（本机实测）：

```text
第九节 start
100
True
70
False
70
70
第九节 end
```

逐块拆开看：

- `private decimal _balance;`：**私有字段**，真正存钱的地方。`private` 表示只有 `Account` 类内部的代码能访问，外面写 `account._balance` 报 CS0122。下划线开头是命名惯例（不是语法要求），让你一眼认出"这是内部字段"。
- `public decimal Balance { get { return _balance; } }`：**只读属性**。只有 `get` 没有 `set`，所以外面能读、不能写——`account.Balance = 100;` 直接编译失败 CS0200。它是公开的"窗口"，窗口后面真正的数据是 `_balance`。
- 为什么不直接写 `public decimal Balance;` 一个公开字段？因为那样外部想改就改，你的校验代码没有地方挂。属性是"带代码的成员"：`get`/`set` 里可以写任意逻辑。第 8 课的自动属性 `{ get; set; }` 只是编译器帮你生成隐藏字段的简写；本节把它展开成"手写字段 + 手写 get/set"，就是为了把逻辑塞进去。
- `if (amount <= 0) return;`：不合法就忽略。真实项目里更常见的是抛异常（第 12 课学），本课先用"忽略 / 纠正"这种温和做法。
- `Withdraw` 返回 `bool`：成功 `true`、失败 `false`，由调用方判断。`amount > _balance` 时直接 `return false`，`_balance` 一分没动。
- `Deposit` 里 `_balance += amount;`：字段就是普通变量，`+=` 照样可用。

**带校验的 set**——把非法值当场纠正。`value` 是 `set` 的隐式参数：外部写 `p.Age = 30` 时，30 自动装进 `value`；校验后你再存进私有字段。`value` 可以被重新赋值（`value = 0;` 合法，本机验证过）：

```csharp
private decimal _price;

public decimal Price
{
    get { return _price; }
    set
    {
        if (value < 0)
        {
            value = 0;      // 非法值纠正为 0
        }
        _price = value;
    }
}
```

上面这段是**类成员**，要写在类的大括号里面——用来替换第 8 课 `Book` 里的 `public decimal Price { get; set; }` 这一行（不是新增；同一类里两个同名属性会报 CS0102）。

金额字面量一律带 `m`（`-5m`、`59.9m`）：`m` 是 decimal 类型的字面量后缀，告诉编译器"这个数字按 decimal 处理"。C# 字面量有默认类型——整数是 `int`，带小数点是 `double`。int 到 decimal 是隐式转换，所以 `-5` 不带 m 也能赋值；但 `-5.5` 不带 m 就是 double，赋值给 decimal 报 CS0266（方法传参时报 CS1503）。金额统一写 `m` 最省心，大小写 M 等价。

构造函数里 `Age = age;` 也会走 `set` 的校验——这就是封装的威力：**所有入口统一把关**，不管谁赋值，都过同一道闸。`new Person("老王", 200)` 出来就是 0 岁。

两个常见简写（知道即可）：

- `public decimal Balance => _balance;` 与 `{ get { return _balance; } }` 完全等价（表达式体属性，本机验证）。
- `public decimal Radius { get; }`：只读自动属性，只能在构造函数里赋值（`public Circle(decimal radius) { Radius = radius; }`），外部赋值同样报 CS0200。适合"造出来就不再变"的值。

> **位置规矩（追加式写法必看）**：第九节的语句插在 `Console.WriteLine($"第八节 end");` 之后、`public class Person` **之前**；`Account` 类加在文件末尾 `Book` 的后面。字段、属性、方法只能写在类的大括号里，写到类外会报 CS9348（本机实测）；类声明必须排在所有顶级语句之后（CS8803）。

常见错误对照（本机实测）：

| 错误写法 | 报错 |
|---|---|
| `account.Balance = 100;` 给只读属性赋值 | CS0200：无法为属性或索引器"Account.Balance"赋值 - 它是只读的 |
| `account._balance = 100;` 外部碰私有字段 | CS0122："Account._balance"不可访问，因为它具有一定的保护级别 |
| 把 `private decimal _price;` 写在类外 | CS9348：编译单元不能直接包含字段、方法或属性等成员 |
| `set { Price = value; }` 忘了 `_`（自己调自己） | 编译能过，运行时 **Stack overflow**（无限递归） |
| 保留旧的自动属性又新增同名 `Price` | CS0102：类型"Book"已经包含"Price"的定义 |
| 校验条件写成 `if (value < 0 && value > 150)` | 编译能过，但两个条件不可能同时成立，非法年龄永远不会被纠正（200 仍是 200） |

1. 抄写本节 `Account` 示例并跑通：存 100 → 打印 `100`；取 30 → `True`、余额 `70`；取 1000 → `False`、余额仍 `70`；存 -50 → 余额仍 `70`。

### 第 10 课 继承与多态（对应打卡：继承、多态）

**继承 = 子类自动拥有父类的成员；多态 = 用父类类型调用，实际执行子类版本。**

JS 里你已经写过：

```js
class Animal {
  constructor(name) { this.name = name; }
  speak() { console.log(`${this.name} 发出了声音`); }
}
class Dog extends Animal {
  constructor(name) { super(name); }
  speak() { console.log(`${this.name}：汪汪！`); }
}
```

C# 对应关系：`extends` → `:`，`super(name)` → `: base(name)`。但有一个关键区别：**JS 的方法默认就是"虚"的（子类同名方法自动覆盖），C# 必须显式写 `virtual` + `override`**——这是本课最容易忘的点。

本节代码（插在第九节 `end` 之后、`public class Person` **之前**；三个新类加在文件末尾 `Account` 后面）：

```csharp
Console.WriteLine($"第十节 start");

var animals = new List<Animal>
{
    new Dog("旺财"),
    new Cat("咪咪")
};

foreach (Animal animal in animals)
{
    animal.Speak();       // 同一句调用，狗叫狗、猫叫猫
}

Animal generic = new Animal("无名");
generic.Speak();

Console.WriteLine($"第十节 end");

public class Animal
{
    public string Name { get; }       // 只读自动属性（第 9 课学过）

    public Animal(string name)
    {
        Name = name;
    }

    public virtual void Speak()       // virtual：允许子类改写
    {
        Console.WriteLine($"{Name} 发出了声音");
    }
}

public class Dog : Animal             // : Animal 表示继承
{
    public Dog(string name) : base(name) { }   // base 调父类构造函数

    public override void Speak()      // override：改写父类方法
    {
        Console.WriteLine($"{Name}：汪汪！");
    }
}

public class Cat : Animal
{
    public Cat(string name) : base(name) { }

    public override void Speak()
    {
        Console.WriteLine($"{Name}：喵~");
    }
}
```

运行结果应该和下面完全一致（本机实测）：

```text
第十节 start
旺财：汪汪！
咪咪：喵~
无名 发出了声音
第十节 end
```

逐块拆开看：

- `class Dog : Animal`：继承。Dog 自动拥有 Animal 的 `Name` 属性和 `Speak()` 方法，不需要重新声明。
- `public Dog(string name) : base(name) { }`：子类构造函数必须让父类构造函数先跑完。`: base(name)` 就是调用 `Animal(string name)`，`Name` 在父类里赋值。**执行顺序：父类构造 → 子类构造**（本机实测：先打印父类内容，再打印子类内容）。
- `public string Name { get; }`：只读自动属性，只能在构造函数里赋值（第 9 课学过）。子类能读（`get` 是 public），不能写（没有 `set`）。
- `virtual`：父类声明"这个方法允许子类改写"。没有 `virtual` 的方法，子类不能用 `override`。
- `override`：子类改写父类方法。方法名、参数、返回类型必须和父类一致。
- **多态**：`List<Animal>` 里装的是 Dog 和 Cat，`foreach` 的变量类型是 `Animal`，但调用 `Speak()` 时执行的是对象**真实类型**的版本——旺财汪汪、咪咪喵。变量的类型决定"能调用什么"，对象的类型决定"实际执行哪一个"。
- `new Animal("无名")` 也能直接造父类对象，调用 `Speak()` 执行父类自己的版本——Animal 不是抽象类。
- `base.Speak();`：在 `override` 里调用父类的原版实现（JS 的 `super.speak()`）。可以先用父类逻辑再补自己的。

`base` 调用的实际效果（本机实测）：

```csharp
public override void Speak()
{
    base.Speak();                     // 先执行父类版本
    Console.WriteLine("再加一句");
}
```

**多态的价值：加类型不改调用代码。** 再写一个 `Bird` 子类，`foreach` 里的代码一行都不用动，它就会自动"啾啾"——对扩展开放。

**父类引用只能调用父类声明的成员。** `Animal animal = new Dog("旺财"); animal.Bark();` 会报 CS1061，因为变量类型是 Animal，编译器只认 Animal 上的成员。要调用 Dog 独有的方法，得用 `Dog` 类型变量。

> **位置规矩（追加式写法必看）**：第十节的语句插在 `Console.WriteLine($"第九节 end");` 之后、`public class Person` **之前**；`Animal`/`Dog`/`Cat` 等新类加在文件末尾（`Account` 后面）。类之间的先后顺序无所谓（Dog 写在 Animal 前面也能编译，本机验证），但类声明必须排在所有顶级语句之后（CS8803）。

常见错误对照（本机实测）：

| 错误写法 | 报错 |
|---|---|
| 父类方法没写 `virtual`，子类写 `override` | CS0506："Dog.Speak()": 继承成员"Animal.Speak()"未标记为 virtual、abstract 或 override，无法进行重写 |
| 子类同名方法忘了写 `override`（只写 `public void Speak()`） | 只有警告 CS0114（隐藏继承成员）；用父类引用调用时仍执行父类版本（实测输出 dog / animal） |
| 子类构造没写 `: base(name)`，父类又没有无参构造 | CS7036：未提供与"Animal.Animal(string)"的所需参数"name"对应的参数 |
| 在没有可重写方法的地方写 `override` | CS0115："Animal.Speak()": 没有找到适合的方法来重写 |
| 用父类引用调用子类独有方法 `animal.Bark()` | CS1061："Animal"未包含"Bark"的定义 |
| `new Dog("x")` 但 Dog 没写带参构造函数 | CS1729："Dog"不包含采用 1 个参数的构造函数 |

动手任务：

1. 抄写本节动物示例并跑通：输出 `旺财：汪汪！`、`咪咪：喵~`、`无名 发出了声音`，start/end 齐全。

### 第 11 课 接口（对应打卡：接口；验收要求“说得清什么是接口”）

**接口 = 一份契约**：只规定“必须会做什么”，不管“怎么做”。

JS 里没有 `interface` 关键字，看的是鸭子类型——**对象只要有同名方法，就能混着用**，编译器不管。TypeScript 的 `interface` 只在编译期检查，编译成 JS 后就消失了。C# 的接口是**真正的类型**：编译器强制“必须实现”，还能像类一样声明变量、装进 `List<>` 循环——这一点和 TS 最像，但检查力度更强。

TS 对照一下（你在前端应该见过）：

```ts
interface IShape {
  name: string;
  area(): number;
}
class Circle implements IShape { /* ... */ }
```

C# 把 `implements` 换成了 `:`——**写法和继承一模一样，含义不同**（下面细说）。

本节代码（插在第十节 `end` 之后、`public class Person` **之前**；`IShape`/`Circle`/`Square` 加在文件末尾 `Bike` 后面）：

```csharp
Console.WriteLine($"第十一节 start");

var shapes = new List<IShape>
{
    new Circle(2),
    new Square(3)
};

foreach (IShape shape in shapes)
{
    Console.WriteLine($"{shape.Name} 面积 = {shape.Area():F2}");
}

Console.WriteLine($"第十一节 end");

public interface IShape
{
    string Name { get; }      // 只要求“能读名字”，不规定怎么读
    double Area();            // 只要求“能算面积”，不写具体算法
}

public class Circle : IShape
{
    public double Radius { get; }

    public Circle(double radius)
    {
        Radius = radius;
    }

    public string Name
    {
        get { return "圆形"; }
    }

    public double Area()
    {
        return Math.PI * Radius * Radius;
    }
}

public class Square : IShape
{
    public double Side { get; }

    public Square(double side)
    {
        Side = side;
    }

    public string Name
    {
        get { return "正方形"; }
    }

    public double Area()
    {
        return Side * Side;
    }
}
```

运行结果应该和下面完全一致（本机实测）：

```text
第十一节 start
圆形 面积 = 12.57
正方形 面积 = 9.00
第十一节 end
```

逐块拆开看：

- `public interface IShape`：接口声明。里面只写成员的**签名**，不写实现（本课范围内）。`I` 开头是 .NET 惯例（`IDisposable`、`IEnumerable` 都这样），不是语法要求，但请照做，别人一眼就知道这是接口。
- `string Name { get; }`：接口里的属性只声明“必须有 getter”。实现类写 `{ get; }` 可以，写 `{ get; set; }` 也可以——多给一个 setter 同样满足契约（本机验证）。但反过来不要过度要求：名字本来只读，接口就写 `{ get; }`；写成 `{ get; set; }` 会强迫每个实现类都公开一个 setter（不写报 CS0535），而这个 setter 往往没有实际意义。
- `double Area();`：只有分号，没有大括号。谁实现谁写算法。几何计算用 `double` 没问题；金额那种要精确的仍用 `decimal`（第 9 课）。
- `class Circle : IShape`：**实现**接口。写法和继承一样用 `:`，但含义不同：Circle 不是“是” IShape，而是“承诺做到 IShape 要求的事”。
- **实现接口不要写 `override`**：这是和第 10 课最容易混的点。`virtual/override` 是父子类之间改写方法用的；实现接口只是提供一个签名相同的 `public` 方法，不加 `override`（加了反而报错）。
- 实现成员必须是 `public`：接口成员默认就是公开契约。写成 `double Area()`（默认 private）会报 CS0737。
- `List<IShape>` / `foreach (IShape shape in shapes)`：**接口当类型用**。循环只认 `Name` 和 `Area()` 两件事，不关心背后是圆还是方——这叫**面向接口编程**：调用方依赖契约，不依赖具体类。第 10 课的多态规则在这里同样成立：变量类型决定“能调用什么”，对象真实类型决定“执行谁的代码”。
- `IShape s = new Circle(2);` 合法：接口变量可以装实现类的对象。`new IShape()` 非法，报 CS0144——接口只有契约没有实现，造不出对象。
- 接口里不能放字段（写 `int Count;` 报 CS0525）：接口只描述行为，不保存状态。`Radius` 是 Circle 自己的属性，接口不关心。

**一个类可以实现多个接口**（本机实测）：

```csharp
public interface IPrintable
{
    void Print();
}

public class Circle : IShape, IPrintable
{
    // 原来的 Radius / Name / Area 一行不动
    public void Print()
    {
        Console.WriteLine($"{Name} 面积 = {Area():F2}");
    }
}
```

之后就能写 `List<IPrintable>` 循环调用 `Print()`，同一个 Circle 对象既可以被当成 `IShape` 用，也可以被当成 `IPrintable` 用。

但**一个类只能继承一个父类**：`class A : B, C`（B、C 都是类）报 CS1721。父类和接口都要时，父类必须写在最前面：`class Circle : Shape, IShape`；反过来写报 CS1722（本机实测）。

接口也能继承接口：`interface INamedShape : IShape`，实现类要把整条链上的成员全部实现（本机实测通过）。

**接口 vs 继承，一句话分清：**

- 继承（`Dog : Animal`）：**is-a**，狗“是”动物。直接拿到父类的字段、构造函数、现成方法，能复用的代码很多。
- 接口（`Circle : IShape`）：**can-do**，圆“能”按形状的方式计算。一个成员都不会白拿，全部自己实现。
- 所以：**想复用代码 → 继承；想规定“必须具备哪些能力、让调用方不关心具体类型” → 接口。** 真实项目里常一起用，比如 `class Circle : Shape, IShape`：拿父类的通用代码，同时承诺接口的能力。

> **位置规矩（追加式写法必看）**：第十一节的语句插在 `Console.WriteLine($"第十节 end");` 之后、`public class Person` **之前**；`IShape`/`Circle`/`Square`（挑战里的 `IPrintable`/`Triangle` 也是）加在文件末尾 `Bike` 后面。接口也是类型声明，必须排在所有顶级语句之后（CS8803）；类/接口之间先后顺序无所谓。

常见错误对照（本机实测）：

| 错误写法 | 报错 |
|---|---|
| `class Circle : IShape` 但没写 `Area()` | CS0535：“Circle”不实现接口成员“IShape.Area()” |
| 接口写 `Name { get; set; }`，实现类只写 getter | CS0535：“Circle”不实现接口成员“IShape.Name.set” |
| 属性写 `get { ... }` 却配一个 `set;`（自动 setter） | 能编译，但赋值写进隐藏字段，getter 永远读不到：`c.Name = "改个名"` 后打印仍是 `Circle`（实测） |
| 实现方法忘了 `public`（默认 private） | CS0737：“Circle.Area()”无法实现接口成员，因为它不是公共的 |
| `new IShape()` | CS0144：无法创建抽象类型或接口“IShape”的实例 |
| 实现接口方法时手滑写了 `override` | CS0115：“Circle.Area()”：没有找到适合的方法来重写 |
| 用接口变量调用实现类独有成员 `shape.Radius` | CS1061：“IShape”未包含“Radius”的定义 |
| 接口里写字段 `int Count;` | CS0525：接口不能包含实例字段 |
| `class A : B, C` 两个都是类 | CS1721：类“A”不能具有多个基类：“B”和“C” |

### 第 12 课 异常处理（对应打卡：异常处理）

**异常 = 运行时出的错。** 不处理，程序当场崩溃（`Unhandled exception.` + 堆栈），后面的代码一行都不执行；处理了，程序就能继续跑或给出友好提示。

JS 里你已经用过同一套关键字：

```js
try {
  const n = Number(input);
  if (Number.isNaN(n)) throw new Error("不是数字");
  console.log(n);
} catch (e) {
  console.log(e.message);
} finally {
  console.log("总会执行");
}
```

C# 的 `try / catch / finally` 长得一样，但有两个关键区别：**C# 按异常类型捕获**（`catch (FormatException)`），JS 的 catch 拿到的是任意值；**C# 的整数除以 0 会抛异常**，JS 的 `1/0` 只会得到 `Infinity`。

本节代码（插在第十一节 `end` 之后、`public class Person` **之前**；本课不需要新类）：

```csharp
Console.WriteLine($"第十二节 start");

try
{
    int number = int.Parse("abc");     // 故意给一个非数字
    Console.WriteLine($"你输入了 {number}");
}
catch (FormatException)
{
    Console.WriteLine("这不是一个数字");
}
catch (Exception ex)
{
    Console.WriteLine($"出错了：{ex.Message}");
}
finally
{
    Console.WriteLine("（不管成功失败都会执行）");
}

try
{
    int number = int.Parse("42");      // 这次能转成功
    Console.WriteLine($"你输入了 {number}");
}
catch (FormatException)
{
    Console.WriteLine("这不是一个数字");
}
finally
{
    Console.WriteLine("（这一句总会执行）");
}

try
{
    int zero = 0;
    Console.WriteLine(10 / zero);      // 整数除以 0：抛异常
}
catch (DivideByZeroException ex)
{
    Console.WriteLine($"除以零：{ex.Message}");
}

Console.WriteLine($"第十二节 end");
```

运行结果应该和下面完全一致（本机实测）：

```text
第十二节 start
这不是一个数字
（不管成功失败都会执行）
你输入了 42
（这一句总会执行）
除以零：Attempted to divide by zero.
第十二节 end
```

逐块拆开看：

- `try { ... }`：把**可能出错**的代码放进来。出了异常，try 里剩下的代码立刻不执行，直接跳到匹配的 catch。
- `catch (FormatException)`：只接“格式不对”这一类异常，`int.Parse("abc")` 抛的就是它。不需要异常对象时可以不写变量名。
- `catch (Exception ex)`：兜底，接住所有异常；`ex.Message` 是运行时给的消息。**catch 的顺序必须具体在前、笼统在后**，反过来报 CS0160。一个 try 可以有多个 catch，但只会执行第一个匹配的。
- `finally { ... }`：不管成功、失败还是提前 `return`，都会执行（本机验证：局部函数里 `try { return 1; } finally { ... }`，先打印 finally，再返回值）。真实项目里用来关文件、关连接、释放资源。
- 第二段 `int.Parse("42")` 成功，所以只打印 `你输入了 42`，然后 finally 照常执行——**成功路径也会走 finally**。
- 第三段 `10 / zero`：整数除零抛 `DivideByZeroException`，被 catch 接住，程序没有崩溃，最后照常打印 `第十二节 end`。
- `ex.Message` 的具体文字随运行时语言环境可能不同（本机是英文），**判断错误类型用 catch 的类型，别去比较 Message 字符串**。

不写 try/catch 会怎样（本机实测）：`int.Parse("abc");` 单独一行，编译能过，运行时输出

```text
Unhandled exception. System.FormatException: The input string 'abc' was not in a correct format.
```

然后程序终止，后面的代码不再执行。**编译错误和运行时异常是两回事**：编译错误（CSxxxx）代码根本跑不起来；异常是代码跑起来了才出错。

常见异常对照（都本机实测）：

| 异常 | 触发方式 | 说明 |
|---|---|---|
| `FormatException` | `int.Parse("abc")` | 字符串不是合法数字 |
| `DivideByZeroException` | `int zero = 0; 10 / zero` | 整数、`decimal` 除以 0 都抛 |
| `IndexOutOfRangeException` | `int[] a = {1,2,3}; a[5]` | 下标越界 |
| `NullReferenceException` | `string? s = null; s.Length` | 对 null 调成员；编译时只有警告 CS8602 |
| `KeyNotFoundException` | 字典用不存在的键取值（第 6 课） | 先用 `ContainsKey` 防 |

**注意 `double` 是例外**：`double zero = 0; 1.0 / zero` 不抛异常，得到 `∞`（Infinity）——这一点和 JS 的 `1/0` 一样。`decimal` 则和整数一样会抛。写计算器时要自己判断除数是否为 0。

**TryParse：不抛异常的转换**——猜数字、计算器循环输入必用：

```csharp
string input = "123abc";

if (int.TryParse(input, out int number))
{
    Console.WriteLine($"转换成功：{number}");
}
else
{
    Console.WriteLine("不是数字，请重输");
}
```

`TryParse` 返回 `bool` 告诉你成不成；`out int number` 是“顺带把结果放进 number”。三个细节（本机实测）：

- `out` 变量在 `if` 条件里声明，作用域延续到整个 if/else 之后，可以直接用。
- 转换失败时 `number` 是 `0`（不是未定义），所以 else 里也能安全读。
- 输入来自用户、格式不可控 → `TryParse`；格式确定正确（比如程序内部常量）→ `Parse`。

**主动抛异常**：`throw`。参数不合法时，与其悄悄纠正，不如让调用方知道：

```csharp
try
{
    SetAge(200);
}
catch (ArgumentException ex)
{
    Console.WriteLine($"参数错误：{ex.Message}");
}

void SetAge(int age)
{
    if (age < 0 || age > 150)
    {
        throw new ArgumentException("年龄必须在 0~150 之间");
    }
    Console.WriteLine($"年龄设置为 {age}");
}
```

输出（本机实测）：

```text
参数错误：年龄必须在 0~150 之间
```

异常会沿着调用链往上找 catch：`SetAge` 里 throw，`SetAge` 自己没有 catch，就抛给调用它的 try；一路没人接，程序就崩溃。第 9 课 `Person.Age` 用的是“非法值纠正为 0”，真实项目里更常见的做法就是像这样抛 `ArgumentException`，让调用方决定怎么处理。局部函数 `SetAge` 放在语句区（类声明之前）即可。

> **位置规矩（追加式写法必看）**：第十二节的语句插在 `Console.WriteLine($"第十一节 end");` 之后、**第一个类型声明之前**。注意你当前的文件里第 11 课的 `public interface IShape` 等类型排在 `Person` 前面，所以这里要插在 `public interface IShape` 之前，而不是 `public class Person` 之前——插到任何类/接口声明之后都会报 CS8803（本机实测）。本课不需要新增类。`SetAge` 这类局部函数也写在语句区，同样要排在所有类型声明之前。

常见错误对照（本机实测）：

| 错误写法 | 结果 |
|---|---|
| `catch (Exception)` 写在 `catch (FormatException)` 前面 | CS0160：上一个 catch 子句已经捕获了此类型或超类型("Exception")的所有异常 |
| `out` 参数在某条返回路径上没赋值 | CS0177：控制离开当前方法之前必须对 out 参数"result"赋值 |
| 不写 try/catch 直接 `int.Parse("abc")` | 能编译；运行时 Unhandled exception. System.FormatException...，程序终止 |
| `string? s = null; s.Length` | 编译只警告 CS8602；运行时 NullReferenceException |
| `int[] a = {1,2,3}; a[5]` | 运行时 IndexOutOfRangeException |
| `int zero = 0; 10 / zero` | 运行时 DivideByZeroException |
| `double zero = 0; 1.0 / zero` | 不报错，得到 ∞（和 JS 的 1/0 一致） |
| `decimal zero = 0m; 1m / zero` | 运行时 DivideByZeroException |
| 常量 `1m / 0m` | 编译期 CS0020：被常数零除（编译器先发现） |

### 练习 A：猜数字游戏

**需求**（验收就按这四条）：

- 程序随机生成 1~100 的整数，循环读你的输入
- 不是数字就提示重输，**不计次数**
- 猜大了/小了给提示；猜中显示用了多少次并结束
- 输入 0、101 这类范围外的数也要提示重输（做了范围校验的话）

**第 1 步——随机数 + 循环骨架**（约 15 分钟）：

会用到：变量、`while (true)`、`TryParse`、`if/else`、`break/continue`、`Random`、`$""`——全是旧知识，想不起来就回看第 3、4、6、12 课。

三个容易写错的地方，先想清楚再动手：

- `random.Next(1, 101)` 的**上限不包含**，所以写 101 才能取到 100（本机实测 10 万次：最小 1、最大 100）
- 随机数在循环**外**生成一次；写在循环里等于每猜一次换一个目标
- `count` 声明在循环外；`count++` 放在 `TryParse` 成功之后，否则输错也计数

参考实现（先自己写，卡住再看）：

```csharp
var random = new Random();
int target = random.Next(1, 101);   // 1~100（上限 101 不包含）
int count = 0;

while (true)
{
    Console.Write("猜一个 1~100 的数字：");
    string input = Console.ReadLine() ?? "";
    if (!int.TryParse(input, out int guess))
    {
        Console.WriteLine("请输入数字！");
        continue;                   // 跳过本次循环，重新来
    }

    count++;

    if (guess < target)
    {
        Console.WriteLine("小了");
    }
    else if (guess > target)
    {
        Console.WriteLine("大了");
    }
    else
    {
        Console.WriteLine($"猜对了！用了 {count} 次");
        break;                      // 退出循环
    }
}
```

`break` = 直接跳出循环；`continue` = 跳过本轮剩余代码，进入下一轮。

跑通后应该看到（本机实测：把 `target` 临时改成 42，依次输入 `abc`、`50`、`25`、`42`）：

```text
猜一个 1~100 的数字：请输入数字！
猜一个 1~100 的数字：大了
猜一个 1~100 的数字：小了
猜一个 1~100 的数字：猜对了！用了 3 次
```

`abc` 没有计数，所以最后是 3 次而不是 4 次——这就是 `continue` 放在 `count++` 之前的效果。

**第 1.5 步——范围校验**（5 行）：解析成功后、计数前补一个判断：

```csharp
    if (guess < 1 || guess > 100)
    {
        Console.WriteLine("请输入 1~100 之间的数字");
        continue;
    }
```

本机实测输入 `0`、`101`、`abc`、`42`（目标 42）：前三个都被拦下且不计数，最后显示 `猜对了！用了 1 次`。注意条件用 `||`（小于 1 **或** 大于 100）；写成 `&&` 永远不成立，等于没校验——第 9 课年龄校验踩过同一个坑。

**第 2 步（挑战）——再来一局**（约 25 分钟）：猜中后问「再来一局吗？(y/n)」，输入 y 重新生成随机数继续，其他键退出。

提示：现在有两层循环——外层管「局」，内层管「这一次猜」。`target` 和 `count` 都必须放进**外层**循环体内，每局重新初始化；猜中后读 y/n，决定 `continue`（开新局）还是 `break`（退出外层）。

参考实现（先自己写）：

```csharp
var random = new Random();

while (true)
{
    int target = random.Next(1, 101);
    int count = 0;

    while (true)
    {
        Console.Write("猜一个 1~100 的数字：");
        string input = Console.ReadLine() ?? "";
        if (!int.TryParse(input, out int guess))
        {
            Console.WriteLine("请输入数字！");
            continue;
        }

        count++;
        if (guess < target)
        {
            Console.WriteLine("小了");
        }
        else if (guess > target)
        {
            Console.WriteLine("大了");
        }
        else
        {
            Console.WriteLine($"猜对了！用了 {count} 次");
            break;
        }
    }

    Console.Write("再来一局吗？(y/n)：");
    string answer = (Console.ReadLine() ?? "").Trim().ToLower();
    if (answer != "y")
    {
        break;
    }
}
```

注意：挑战版是**替换**第 1 步的整段代码，不是追加。`random` 只能声明一次，两份都留着会报 CS0128（第 8 课踩过重名）。

本机实测（目标固定 42，输入 `42 → y → 7 → 42 → n`）：

```text
猜一个 1~100 的数字：猜对了！用了 1 次
再来一局吗？(y/n)：猜一个 1~100 的数字：小了
猜一个 1~100 的数字：猜对了！用了 2 次
再来一局吗？(y/n)：
```

第二局只用了 2 次，说明 `count` 每局确实归零了。

常见错误（都本机实测）：

| 写法 | 结果 |
|---|---|
| `random.Next(1, 100)` | 永远猜不到 100（上限不包含）|
| `target` 写在循环里 | 每轮换目标，几乎永远猜不中 |
| `count++` 放在 `TryParse` 之前 | 输错也计一次 |
| `int.Parse(input)` | 输入 `abc` 直接抛 FormatException，程序崩溃（第 12 课）|
| 顶层语句里用 `return` 代替 `break` | 程序整体结束，后面的练习 B 根本不执行 |

### 练习 B：简单计算器

**需求**：

- 输入 `3 + 5` 这样的算式回车，得到 `3 + 5 = 8`
- 支持 `+ - * /` 四则运算；输入 `q` 退出
- 除零、非数字、格式错误、不认识的运算符都不能崩

**第 1 步——主循环 + switch**（约 30 分钟）：

会用到：`while`、`Split`、`TryParse`、`switch`、`continue/break`。先想清楚这四点：

- 先判断 `q` 再解析；否则 `q` 会先撞上「格式不对」
- `Split(' ')` 按**单个空格**切：`3 + 5` 正好 3 段，`3+5` 和 `3  +  5` 都不行（第 2 步再改进）
- 两个数一起判断：`!double.TryParse(...) || !double.TryParse(...)`
- `double` 除以 0 **不抛异常**（第 12 课），得到 `∞`，所以必须自己 `if (b == 0)`；整数和 `decimal` 才会抛

参考实现（先自己写，卡住再看）：

```csharp
while (true)
{
    Console.Write("输入算式（如 3 + 5），输入 q 退出：");
    string line = Console.ReadLine() ?? "";
    if (line.Trim().ToLower() == "q")
    {
        break;
    }

    string[] parts = line.Split(' ');
    if (parts.Length != 3)
    {
        Console.WriteLine("格式不对，示例：3 + 5");
        continue;
    }

    if (!double.TryParse(parts[0], out double a) ||
        !double.TryParse(parts[2], out double b))
    {
        Console.WriteLine("数字解析失败");
        continue;
    }

    switch (parts[1])
    {
        case "+":
            Console.WriteLine($"{a} + {b} = {a + b}");
            break;
        case "-":
            Console.WriteLine($"{a} - {b} = {a - b}");
            break;
        case "*":
            Console.WriteLine($"{a} * {b} = {a * b}");
            break;
        case "/":
            if (b == 0)
            {
                Console.WriteLine("除数不能为 0");
            }
            else
            {
                Console.WriteLine($"{a} / {b} = {a / b}");
            }
            break;
        default:
            Console.WriteLine("只支持 + - * /");
            break;
    }
}
```

跑通后对照（本机实测，依次输入 `3 + 5`、`10 / 0`、`3 / 5`、`abc + 1`、`3+5`、`3  +  5`、`3 ^ 5`，最后 `q`；为省版面省略了每行开头的输入提示）：

```text
3 + 5 = 8
除数不能为 0
3 / 5 = 0.6
数字解析失败
格式不对，示例：3 + 5
格式不对，示例：3 + 5
只支持 + - * /
```

两个值得注意的地方：`3 / 5` 是 `0.6` 而不是整数除法；`1 / 3` 会显示 `0.3333333333333333`（`double` 的默认显示，不是格式化后的结果）。`3+5` 和 `3  +  5` 走「格式不对」是 `Split(' ')` 的预期行为，下一步可以改进。

**第 2 步（挑战，二选一，约 25 分钟）**：

A. **容忍多余空格**：把 `line.Split(' ')` 改成 `line.Split(' ', StringSplitOptions.RemoveEmptyEntries)`。本机实测 `3  +  5`、前后带空格的 `  7 * 6  ` 都能算；`3+5`（完全没空格）仍然不支持——那需要正则或手动找运算符，超纲，选做。

B. **抽方法**：把四则运算搬进 `bool TryCalculate(double a, double b, string op, out double result)`，照第 12 课 `TryDivide` 的写法：成功赋值并返回 `true`；除零、未知运算符返回 `false`。主循环只管输入输出，`false` 时统一提示「算不了：检查运算符或除数」。本机实测：`3 + 5 = 8`；`10 / 0`、`3 ^ 5` 都提示算不了；`3 / 5 = 0.6`。

> 如果你想按原样写 `double Calculate(...)` 也可以：那就要在**主循环里**先判断 `b == 0` 和运算符是否合法，再调用它——错误处理别留在方法里只打印一句话，否则会输出 `10 / 0 = 0` 这种误导结果。

常见错误（都本机实测）：

| 写法 | 结果 |
|---|---|
| `int.TryParse(parts[0], ...)` | 小数（3.5、0.5）全被拒绝；计算器必须用 `double` |
| 用 `double.Parse` 不判断 | 输入 `abc` 直接抛 FormatException |
| 忘记判 `b == 0` | `10 / 0 = ∞`，不崩但答案是错的 |
| `parts[1]` / `parts[2]` 写反 | 运算符和第二个数错位，switch 走 default |
| `line == "q"` | `Q`、`q `（带空格）都退不出去；用 `Trim().ToLower()` |

    public void ShowMonthlyStats()
    {
        if (_items.Count == 0)
        {
            Console.WriteLine("还没有任何记录，无法统计。");
            return;
        }

        var incomeByMonth = new Dictionary<string, decimal>();
        var expenseByMonth = new Dictionary<string, decimal>();

        foreach (Transaction t in _items)
        {
            string month = t.Date.ToString("yyyy-MM");   // 如 2026-10

            if (t.IsIncome)
            {
                if (!incomeByMonth.ContainsKey(month))
                {
                    incomeByMonth[month] = 0m;
                }
                incomeByMonth[month] += t.Amount;
            }
            else
            {
                if (!expenseByMonth.ContainsKey(month))
                {
                    expenseByMonth[month] = 0m;
                }
                expenseByMonth[month] += t.Amount;
            }
        }

        var months = new List<string>();
        foreach (var kv in incomeByMonth)
        {
            months.Add(kv.Key);
        }
        foreach (var kv in expenseByMonth)
        {
            if (!months.Contains(kv.Key))
            {
                months.Add(kv.Key);
            }
        }
        months.Sort();

        foreach (string month in months)
        {
            decimal income = incomeByMonth.ContainsKey(month) ? incomeByMonth[month] : 0m;
            decimal expense = expenseByMonth.ContainsKey(month) ? expenseByMonth[month] : 0m;
            Console.WriteLine($"{month}  收入 {income:F2}  支出 {expense:F2}  结余 {income - expense:F2}");
        }
    }
