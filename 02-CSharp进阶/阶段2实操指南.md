### 第 1 课 泛型（对应打卡：泛型）

**为什么需要泛型**：你阶段 1 用过 `List<Transaction>`，尖括号里的就是类型参数。没有泛型，想写一个“取最大值”的方法，得给 `int`、`double`、`string` 各写一遍；用 `object` 又要强制转换，类型错了运行时才炸。

```csharp
T Max<T>(T a, T b) where T : IComparable<T>
{
    return a.CompareTo(b) > 0 ? a : b;
}

Console.WriteLine(Max(3, 5));                // 5
Console.WriteLine(Max(1.5, 2.5));            // 2.5
Console.WriteLine(Max("apple", "banana"));   // banana

void PrintAll<T>(IEnumerable<T> items)
{
    Console.WriteLine(string.Join(", ", items));
}

PrintAll(new List<int> { 1, 2, 3 });         // 1, 2, 3
PrintAll(new[] { "a", "b" });                // a, b

var intBox = new Box<int>(42);
var textBox = new Box<string>("hello");
Console.WriteLine(intBox);                   // Box(42)
Console.WriteLine(textBox);                  // Box(hello)
Console.WriteLine(intBox.Value + 8);         // 50

public class Box<T>
{
    public T Value { get; set; }

    public Box(T value)
    {
        Value = value;
    }

    public override string ToString() => $"Box({Value})";
}
```

运行输出（本机实测）：

```text
5
2.5
banana
1, 2, 3
a, b
Box(42)
Box(hello)
50
```

`where T : IComparable<T>` 是**泛型约束**：告诉编译器“T 一定能比较大小”，否则 `a.CompareTo(b)` 编译不过。

错误写法（会报 CS1061）：

```csharp
T Max<T>(T a, T b)
{
    return a.CompareTo(b) > 0 ? a : b;   // 编译器：T 没有 CompareTo
}
```

正确写法就是上面加了 `where` 的版本。

常见约束：

| 约束 | 含义 |
|---|---|
| `where T : IComparable<T>` | T 必须能和自己比较 |
| `where T : class` | T 必须是引用类型 |
| `where T : struct` | T 必须是值类型 |
| `where T : new()` | T 必须有无参构造函数 |
| `where T : 基类名` | T 必须继承某个类 / 实现某个接口 |

> 和 JS / TS 对比：TS 的泛型编译后会被擦除，运行时拿不到 `T`；C# 泛型在运行时保留类型信息，`List<int>` 和 `List<string>` 是两个真实类型，也不会像 `object` 那样装箱。JS 数组什么都装，错了运行时才发现；C# 的 `List<int>` 连 `Add("abc")` 都编译不过。

### 第 2 课 委托与事件（对应打卡：委托、Lambda）

**委托（delegate）** = “方法的类型”。变量里可以存一个方法，像调用方法一样调用这个变量。JS 里函数是一等公民，直接把函数传来传去；C# 是静态类型语言，要用委托声明“这个变量能存什么签名的方法”。

C# 内置了三个最常用的委托，日常基本不用自己声明：

| 委托 | 签名 | 用途 |
|---|---|---|
| `Action` | 无返回值 | `Action<string> log` |
| `Action<T1, T2>` | 无返回值，带参数 | `Action<int, string>` |
| `Func<T1, TResult>` | 有返回值 | `Func<int, int, int> add` |
| `Predicate<T>` | 返回 `bool` | `Predicate<int> isEven` |

`Program.cs` 全部内容：

```csharp
MathOp add = (a, b) => a + b;
MathOp multiply = (a, b) => a * b;
Console.WriteLine(add(3, 4));        // 7
Console.WriteLine(multiply(3, 4));   // 12

Action<string> log = message => Console.WriteLine($"[LOG] {message}");
log("程序启动");                      // [LOG] 程序启动

Func<int, int, int> sub = (a, b) => a - b;
Console.WriteLine(sub(10, 3));       // 7

Predicate<int> isEven = n => n % 2 == 0;
Console.WriteLine(isEven(4));        // True

// 多播：一个委托变量可以挂多个方法，按顺序执行
Action<string> pipeline = log;
pipeline += message => Console.WriteLine($"[FILE] {message}");
pipeline("保存成功");                 // 先 [LOG]，再 [FILE]

var counter = new Counter();
counter.Reached += n => Console.WriteLine($"计数到达 {n}，提醒一下");
for (int i = 0; i < 10; i++)
{
    counter.Add();
}

public delegate int MathOp(int a, int b);   // 自定义委托：类型声明放文件末尾

public class Counter
{
    public event Action<int>? Reached;      // 事件：外部只能 += / -=
    private int _count;

    public void Add()
    {
        _count++;
        if (_count % 5 == 0)
        {
            Reached?.Invoke(_count);        // ?. 防止没人订阅时 NullReferenceException
        }
    }
}
```

运行输出（本机实测）：

```text
7
12
[LOG] 程序启动
7
True
[LOG] 保存成功
[FILE] 保存成功
计数到达 5，提醒一下
计数到达 10，提醒一下
```

**事件（event）** 是对委托的封装，典型用法是“发布者—订阅者”：

- `Counter` 是发布者，`Reached` 是事件
- 外部用 `counter.Reached += ...` 订阅，`-=` 取消
- 外部**不能** `counter.Reached = null`，也**不能** `counter.Reached()` 直接触发；只有 `Counter` 类内部能 `Invoke`
- 触发前用 `?.Invoke(...)`，否则没人订阅时会空引用

> 和 JS 对比：`Reached += handler` 很像 `element.addEventListener("click", handler)`，但 C# 的事件是类型安全的（签名不对编译不过），而且没有 DOM，纯 C# 对象之间也能用。

### 第 3 课 Lambda 表达式（对应打卡：Lambda）

Lambda 就是“匿名方法”，语法 `(参数) => 表达式`。JS 的箭头函数 `(a, b) => a + b` 几乎一模一样；区别是 C# 的 lambda 不会像 JS 那样重绑 `this`，也没有 `arguments`。

`Program.cs` 全部内容：

```csharp
List<int> numbers = new() { 5, 2, 8, 1, 9, 4 };

numbers.Sort((a, b) => a - b);
Console.WriteLine(string.Join(", ", numbers));   // 1, 2, 4, 5, 8, 9

var evens = numbers.FindAll(n => n % 2 == 0);
Console.WriteLine(string.Join(", ", evens));     // 2, 4, 8

int threshold = 4;
var big = numbers.FindAll(n => n > threshold);   // 捕获外部变量 threshold
Console.WriteLine(string.Join(", ", big));       // 5, 8, 9

Func<int, int> square = n => n * n;
Console.WriteLine(square(6));                    // 36

// 多行 lambda 要用大括号 + return
Func<int, int, int> max = (a, b) =>
{
    int result = a > b ? a : b;
    return result;
};
Console.WriteLine(max(3, 7));                    // 7

// 陷阱：for 循环的 i 只有一个，三个 lambda 捕获的是同一个 i
var forActions = new List<Action>();
for (int i = 0; i < 3; i++)
{
    forActions.Add(() => Console.WriteLine($"for: {i}"));
}
foreach (var action in forActions) action();     // for: 3 三次

// foreach 每次迭代都是新变量，所以输出 0、1、2
var foreachActions = new List<Action>();
foreach (int n in new[] { 0, 1, 2 })
{
    foreachActions.Add(() => Console.WriteLine($"foreach: {n}"));
}
foreach (var action in foreachActions) action();  // foreach: 0 / 1 / 2
```

运行输出（本机实测）：

```text
1, 2, 4, 5, 8, 9
2, 4, 8
5, 8, 9
36
7
for: 3
for: 3
for: 3
foreach: 0
foreach: 1
foreach: 2
```

**闭包**：lambda 能“记住”外部变量（`threshold`、`i`、`n`）。记住的是**变量本身**，不是当时的值——所以 `for` 循环结束后 `i` 是 3，三个 lambda 都打印 3。要固定当前值，就在循环里复制一份：

```csharp
for (int i = 0; i < 3; i++)
{
    int copy = i;
    forActions.Add(() => Console.WriteLine($"for: {copy}"));
}
```

### 第 4 课 LINQ 入门：Where / Select（对应打卡：LINQ）

**LINQ** = Language Integrated Query，用方法链操作集合，像 SQL 一样筛选、投影、排序、分组。它建立在扩展方法和 lambda 之上——前两课就是为它做准备。

准备一份商品数据（本课和后面两课都用它）：

```csharp
var products = new List<Product>
{

    new() { Name = "显示器", Category = "数码", Price = 1299m, Stock = 5 },
    new() { Name = "咖啡豆", Category = "食品", Price = 89m, Stock = 30 },
    new() { Name = "跑步鞋", Category = "运动", Price = 499m, Stock = 8 },
    new() { Name = "鼠标垫", Category = "数码", Price = 39m, Stock = 50 },
    new() { Name = "牛奶", Category = "食品", Price = 12.5m, Stock = 100 }
```

`Program.cs` 全部内容：

```csharp
var products = new List<Product>
{
    new() { Name = "机械键盘", Category = "数码", Price = 399m, Stock = 12 },
    new() { Name = "显示器", Category = "数码", Price = 1299m, Stock = 5 },
    new() { Name = "咖啡豆", Category = "食品", Price = 89m, Stock = 30 },
    new() { Name = "跑步鞋", Category = "运动", Price = 499m, Stock = 8 },
    new() { Name = "鼠标垫", Category = "数码", Price = 39m, Stock = 50 },
    new() { Name = "牛奶", Category = "食品", Price = 12.5m, Stock = 100 }
};

// Where：过滤，留下满足条件的
var expensive = products.Where(p => p.Price > 300).ToList();
Console.WriteLine("价格 > 300：");
foreach (var p in expensive)
{
    Console.WriteLine($"{p.Name} {p.Price:C}");
}

// Select：投影，把每个元素变成另一种形状
var names = products.Select(p => p.Name).ToList();
Console.WriteLine(string.Join("、", names));

var brief = products.Select(p => new { p.Name, p.Price });
foreach (var item in brief)
{
    Console.WriteLine($"{item.Name}: {item.Price:C}");
}

// 延迟执行：查询定义时没运行
var cheapQuery = products.Where(p => p.Price < 100);
Console.WriteLine($"添加前：{cheapQuery.Count()} 条");      // 3

products.Add(new Product { Name = "笔记本", Category = "文具", Price = 9.9m, Stock = 200 });
Console.WriteLine($"添加后：{cheapQuery.Count()} 条");      // 4 —— 查询重新执行，看到了新元素

products.RemoveAt(products.Count - 1);
Console.WriteLine($"移除后：{cheapQuery.Count()} 条");      // 3

public class Product
{
    public string Name { get; set; } = "";
    public string Category { get; set; } = "";
    public decimal Price { get; set; }
    public int Stock { get; set; }
}
```

运行输出（本机实测）：

```text
价格 > 300：
机械键盘 ¥399.00
显示器 ¥1,299.00
跑步鞋 ¥499.00
机械键盘、显示器、咖啡豆、跑步鞋、鼠标垫、牛奶
机械键盘: ¥399.00
显示器: ¥1,299.00
咖啡豆: ¥89.00
跑步鞋: ¥499.00
鼠标垫: ¥39.00
牛奶: ¥12.50
添加前：3 条
添加后：4 条
移除后：3 条
```

**延迟执行**是 LINQ 最重要的特性之一：

- `products.Where(...)` 返回的是 `IEnumerable<Product>`，只是“查询描述”，不是结果
- `foreach`、`ToList()`、`Count()`、`Sum()` 等**枚举**操作才真正执行
- 所以查询定义后原集合变了，再枚举会得到新结果
- 想“拍照”固定下来，就 `.ToList()`：
  ```csharp
  var snapshot = products.Where(p => p.Price < 100).ToList();
  ```

> 和 JS 对比：`array.filter()` / `map()` 是**立即**返回新数组；LINQ 是**延迟**的，链式调用只是拼查询。JS 的 `map/filter/reduce` 链 ≈ LINQ 的 `Select/Where/Aggregate`，但 LINQ 有类型检查，还有 `GroupBy`、`Join` 等 SQL 风格操作。

### 第 5 课 LINQ 排序、分组、聚合（对应打卡：LINQ）

`Program.cs` 全部内容（商品数据同上一课）：

```csharp
var products = new List<Product>
{
    new() { Name = "机械键盘", Category = "数码", Price = 399m, Stock = 12 },
    new() { Name = "显示器", Category = "数码", Price = 1299m, Stock = 5 },
    new() { Name = "咖啡豆", Category = "食品", Price = 89m, Stock = 30 },
    new() { Name = "跑步鞋", Category = "运动", Price = 499m, Stock = 8 },
    new() { Name = "鼠标垫", Category = "数码", Price = 39m, Stock = 50 },
    new() { Name = "牛奶", Category = "食品", Price = 12.5m, Stock = 100 }
};

// 排序：OrderBy 升序，OrderByDescending 降序，ThenBy 第二排序键
var sorted = products.OrderBy(p => p.Price).ThenBy(p => p.Name);
Console.WriteLine("按价格升序：");
foreach (var p in sorted)
{
    Console.WriteLine($"{p.Name} {p.Price:C}");
}

// 分组 + 聚合：每个分类几件、合计多少钱、均价多少
var byCategory = products
    .GroupBy(p => p.Category)
    .Select(g => new
    {
        Category = g.Key,
        Count = g.Count(),
        Total = g.Sum(p => p.Price),
        Average = g.Average(p => p.Price)
    })
    .OrderByDescending(x => x.Total);

foreach (var item in byCategory)
{
    Console.WriteLine($"{item.Category}: {item.Count} 件，合计 {item.Total:C}，均价 {item.Average:C}");
}

// 分组后还能拿到组里的原始元素
foreach (var g in products.GroupBy(p => p.Category))
{
    Console.WriteLine($"{g.Key}: {string.Join("、", g.Select(p => p.Name))}");
}

Console.WriteLine($"总价 {products.Sum(p => p.Price):C}");
Console.WriteLine($"均价 {products.Average(p => p.Price):C}");
Console.WriteLine($"最贵 {products.Max(p => p.Price):C}");
Console.WriteLine($"最便宜 {products.Min(p => p.Price):C}");

public class Product
{
    public string Name { get; set; } = "";
    public string Category { get; set; } = "";
    public decimal Price { get; set; }
    public int Stock { get; set; }
}
```

运行输出（本机实测）：


### 第 6 课 LINQ 查找与判定（对应打卡：LINQ）

`Program.cs` 全部内容（商品数据同上）：

```csharp
var products = new List<Product>
{
    new() { Name = "机械键盘", Category = "数码", Price = 399m, Stock = 12 },
    new() { Name = "显示器", Category = "数码", Price = 1299m, Stock = 5 },
    new() { Name = "咖啡豆", Category = "食品", Price = 89m, Stock = 30 },
    new() { Name = "跑步鞋", Category = "运动", Price = 499m, Stock = 8 },
    new() { Name = "鼠标垫", Category = "数码", Price = 39m, Stock = 50 },
    new() { Name = "牛奶", Category = "食品", Price = 12.5m, Stock = 100 }
};

// First：找第一个，找不到会抛异常
var first = products.First(p => p.Price > 1000);
Console.WriteLine($"第一件 >1000：{first.Name}");          // 显示器

// FirstOrDefault：找不到返回 null（引用类型）
var maybe = products.FirstOrDefault(p => p.Price > 5000);
Console.WriteLine(maybe is null ? "没有找到" : maybe.Name); // 没有找到

// Any / All：判断“有没有” / “是不是都”
Console.WriteLine($"有缺货吗：{products.Any(p => p.Stock == 0)}");       // False
Console.WriteLine($"都大于 0 元吗：{products.All(p => p.Price > 0)}");   // True
Console.WriteLine($"数码产品数量：{products.Count(p => p.Category == "数码")}"); // 3

// 排序 + 分页：取前 3 名；跳过 2 个再取 2 个
var top3 = products.OrderByDescending(p => p.Price).Take(3).ToList();
Console.WriteLine($"前三贵：{string.Join("、", top3.Select(p => p.Name))}");

var page2 = products.OrderBy(p => p.Price).Skip(2).Take(2).ToList();
Console.WriteLine($"第 2 页：{string.Join("、", page2.Select(p => p.Name))}");

// Distinct：去重
var categories = products.Select(p => p.Category).Distinct();
Console.WriteLine($"分类：{string.Join("、", categories)}");

// Single：有且只有一个才返回，0 个或多个都抛异常
var only = products.Single(p => p.Name == "显示器");
Console.WriteLine($"Single：{only.Name}");

// MaxBy：直接拿“价格最大的那个元素”
var mostExpensive = products.MaxBy(p => p.Price);
Console.WriteLine($"MaxBy：{mostExpensive?.Name}");

try
{
    var bad = products.Single(p => p.Category == "数码");   // 有 3 个，抛异常
    Console.WriteLine(bad.Name);
}
catch (InvalidOperationException ex)
{
    Console.WriteLine($"Single 抛异常：{ex.Message}");
}

public class Product
{
    public string Name { get; set; } = "";
    public string Category { get; set; } = "";
    public decimal Price { get; set; }
    public int Stock { get; set; }
}
```

运行输出（本机实测）：

```text

没有找到

都大于 0 元吗：True

第 2 页：咖啡豆、机械键盘

Single：显示器
MaxBy：显示器
Single 抛异常：Sequence contains more than one matching element
```

**First vs FirstOrDefault vs Single**

| 方法 | 找到 1 个 | 找到多个 | 一个都没有 |
|---|---|---|---|
| `First(...)` | 返回第一个 | 返回第一个 | 抛 `InvalidOperationException` |
| `FirstOrDefault(...)` | 返回第一个 | 返回第一个 | 返回 `null`（引用类型）或默认值（值类型） |
| `Single(...)` | 返回它 | 抛异常 | 抛异常 |
| `SingleOrDefault(...)` | 返回它 | 抛异常 | 返回 `null` / 默认值 |

**值类型的坑**：`List<int>` 上 `FirstOrDefault` 找不到时返回 `0`，不是 `null`，你没法区分“真的 0”和“没找到”。这种情况先 `Any()` 判断，或者用 `int?`：

```csharp
List<int> numbers = new() { 1, 3, 5 };
int? found = numbers.Where(n => n % 2 == 0).Select(n => (int?)n).FirstOrDefault();
Console.WriteLine(found is null ? "没有偶数" : found.Value.ToString());
```

### 第 7 课 async / await（对应打卡：async / await）

**解决什么问题**：下载文件、读写磁盘、访问数据库时，CPU 其实在等。同步写法 `Thread.Sleep(1000)` 会把整个线程卡住；异步写法 `await Task.Delay(1000)` 会把线程让出去，等时间到了再继续。控制台程序里差别不明显，但 Web 服务器里一个线程很贵——这是后面 ASP.NET Core 的基础。

`Program.cs` 全部内容：

```csharp
using System.Diagnostics;

Console.WriteLine("1. 开始");

var stopwatch = Stopwatch.StartNew();
await DownloadAsync("文件A", 800);
await DownloadAsync("文件B", 800);
await DownloadAsync("文件C", 800);
stopwatch.Stop();
Console.WriteLine($"串行耗时约 {stopwatch.ElapsedMilliseconds} 毫秒");

stopwatch.Restart();
await Task.WhenAll(
    DownloadAsync("文件A", 800),
    DownloadAsync("文件B", 800),
    DownloadAsync("文件C", 800));
stopwatch.Stop();
Console.WriteLine($"并行耗时约 {stopwatch.ElapsedMilliseconds} 毫秒");

try
{
    await FailAsync();
}
catch (InvalidOperationException ex)
{
    Console.WriteLine($"捕获：{ex.Message}");
}

long sum = await Task.Run(() =>
{
    long total = 0;
    for (int i = 1; i <= 10_000_000; i++) total += i;
    return total;
});
Console.WriteLine($"Task.Run 计算结果：{sum}");

async Task DownloadAsync(string name, int delay)
{
    Console.WriteLine($"{name} 开始下载");
    await Task.Delay(delay);
    Console.WriteLine($"{name} 下载完成");
}

async Task FailAsync()
{
    await Task.Delay(100);
    throw new InvalidOperationException("下载失败");
}
```

运行输出（本机实测，毫秒数每次略有不同）：

```text
1. 开始
文件A 开始下载
文件A 下载完成
文件B 开始下载
文件B 下载完成
文件C 开始下载
文件C 下载完成
串行耗时约 2433 毫秒
文件A 开始下载
文件B 开始下载
文件C 开始下载
文件C 下载完成
文件A 下载完成
文件B 下载完成
并行耗时约 806 毫秒
捕获：下载失败
Task.Run 计算结果：50000005000000
```

关键点：

- `async Task` 表示“这个方法是异步的，没有返回值”；`async Task<T>` 表示“异步且有返回值 `T`”
- 方法里至少有一个 `await`；`await` 会暂停当前方法，把线程让出去，等任务完成再继续
- 顶层语句（顶级语句）可以直接写 `await`，编译器会自动生成异步 `Main`
- `Task.WhenAll(...)` 等所有任务一起完成，相当于 JS 的 `Promise.all`
- 异步方法里抛出的异常，会在 `await` 的地方抛出，用普通 `try/catch` 捕获
- `Task.Run(...)` 把 CPU 密集的工作丢到线程池；I/O 操作用自带的异步 API（`File.ReadAllTextAsync`、`HttpClient.GetStringAsync`），不要用 `Task.Run` 包同步 I/O

**不要这样写**：

```csharp
// 错误：.Result / .Wait() 会阻塞线程，Web 里可能死锁
var text = File.ReadAllTextAsync(path).Result;
File.ReadAllTextAsync(path).Wait();

// 错误：async void 无法被 await，异常也没人接
async void DoSomething() { ... }
```

`async void` 只用于事件处理器（比如 `button_Click`）；自己写的方法一律 `async Task`。

> 和 JS 对比：`Task` ≈ `Promise`，`async/await` 写法几乎一样，`Task.WhenAll` ≈ `Promise.all`，`Task.Delay` ≈ `setTimeout` 的 Promise 版。区别：C# 的 async 方法在遇到第一个 `await` 之前是**同步执行**的；JS 的 async 函数也是同步执行到第一个 await，这一点其实一致。

### 第 9 课 JSON 序列化（对应打卡：文件读写、JSON 序列化）

`Program.cs` 全部内容：

```csharp
using System.Text.Encodings.Web;
using System.Text.Json;
using System.Text.Json.Serialization;
using System.Text.Unicode;

var options = new JsonSerializerOptions
{
    WriteIndented = true,                  // 缩进，方便人看
    PropertyNameCaseInsensitive = true,    // 读的时候属性名不区分大小写
    Encoder = JavaScriptEncoder.Create(UnicodeRanges.All)   // 中文不转成 \uXXXX
};
options.Converters.Add(new JsonStringEnumConverter());      // 枚举写成 "Expense" 而不是 1

var transactions = new List<Transaction>
{
    new() { Date = new DateTime(2026, 11, 6, 9, 30, 0), Type = TransactionType.Expense, Amount = 23.5m, Category = "餐饮", Note = "早饭" },
    new() { Date = new DateTime(2026, 11, 6, 18, 0, 0), Type = TransactionType.Income, Amount = 5000m, Category = "工资", Note = "11 月工资" }
};

string dataDir = Path.Combine(AppContext.BaseDirectory, "data");
Directory.CreateDirectory(dataDir);
string jsonPath = Path.Combine(dataDir, "transactions.json");

string json = JsonSerializer.Serialize(transactions, options);
await File.WriteAllTextAsync(jsonPath, json);
Console.WriteLine($"已写入 {jsonPath}");
Console.WriteLine(await File.ReadAllTextAsync(jsonPath));

string readBack = await File.ReadAllTextAsync(jsonPath);
var loaded = JsonSerializer.Deserialize<List<Transaction>>(readBack, options) ?? new List<Transaction>();
Console.WriteLine($"加载 {loaded.Count} 条，第一条：{loaded[0].Category} {loaded[0].Amount:C}");

string broken = "{ 这不是合法 JSON }";
try
{
    JsonSerializer.Deserialize<List<Transaction>>(broken, options);
}
catch (JsonException ex)
{
    Console.WriteLine($"JSON 格式错误：{ex.Message}");
}

string partial = """[{"Date":"2026-11-07T00:00:00","Type":"Expense","Amount":12.3,"Note":"地铁"}]""";
var partialList = JsonSerializer.Deserialize<List<Transaction>>(partial, options) ?? new();
Console.WriteLine($"缺少 Category 字段时：\"{partialList[0].Category}\"（空字符串）");

public enum TransactionType { Income, Expense }

public class Transaction
{
    public DateTime Date { get; set; }
    public TransactionType Type { get; set; }
    public decimal Amount { get; set; }
    public string Category { get; set; } = "";
    public string Note { get; set; } = "";
}
```

运行输出（本机实测，路径省略部分）：

```text

[
  {
    "Date": "2026-11-06T09:30:00",

缺少 Category 字段时：""（空字符串）
```

**System.Text.Json 的 6 个坑**：

1. **只序列化公共属性，不序列化公共字段**。`public decimal Amount;` 是字段，写出来不会有它；必须 `public decimal Amount { get; set; }`。
2. **属性名默认区分大小写**（反序列化时）。JSON 里写 `"amount"`、类里是 `Amount`，默认读不到，值是 0。`PropertyNameCaseInsensitive = true` 解决。
3. **枚举默认写成数字**（`0`、`1`），可读性差。`JsonStringEnumConverter` 写成 `"Income"`、`"Expense"`。
4. **中文默认转义成 `\u9910\u996e`**，文件能读但人看不懂。`JavaScriptEncoder.Create(UnicodeRanges.All)` 保留中文。
5. **JSON 格式错会抛 `JsonException`**，必须 `try/catch`；`Deserialize` 还可能返回 `null`，用 `?? new List<...>()` 兜底。
6. **私有 setter / 只读属性**默认不能反序列化。用 `{ get; set; }`，或者给 record 用构造函数（第 11 课）。

> 和 JS 对比：`JSON.stringify` / `JSON.parse` 是无类型的，字段名写错运行时才发现；C# 的 `JsonSerializer` 是强类型的，但“属性名、大小写、枚举、字段/属性”这些规则要自己配。

**enum（枚举）**：一组有名字的常量，底层是整数。比 `bool IsIncome`、`string type` 更清楚，编译器也能帮你检查。

- `Enum.GetValues<T>()` 遍历所有值
- `Enum.TryParse<T>("Expense", out var x)` 从字符串解析（解析失败返回 `false`）
- 默认从 0 开始编号；可以显式写 `Income = 1`
- JSON 里想要字符串，用第 9 课的 `JsonStringEnumConverter`

**struct（结构体）**：值类型。赋值、传参都是**复制**，不是共享引用。适合小的、不可变的数据（坐标、金额+币种、温度）。

- `var p2 = p1;` 后改 `p2.X` 不影响 `p1`
- 默认值：`new Point()` 的 X/Y 都是 0
- 可变 struct 容易踩坑（改副本以为改了原对象），优先写 `readonly struct`
- struct 不能继承，不能为 null（除非 `Point?`）

**record（记录）**：默认是引用类型，但**按值相等**，编译器自动生成构造函数、属性、`ToString`、`==`、`GetHashCode`，特别适合 DTO / 查询结果。

- `public record Money(decimal Amount, string Currency);` 是“位置记录”，属性是 `init` 只读的
- `money1 with { Amount = 20m }` 生成一个新对象，原对象不变
- 两个 record 的所有属性相等，`==` 就是 `True`（class 默认是引用相等）
- `record struct` 是值类型的 record；`record class` 是默认的引用类型 record

| | class | struct | record |
|---|---|---|---|
| 类型 | 引用 | 值 | 默认引用 |
| 赋值 | 复制引用 | 复制值 | 复制引用（但按值比较） |
| `==` | 引用相等 | 值相等 | 值相等 |
| 可变性 | 可自由改 | 可改（建议 readonly） | 位置属性 init-only，用 `with` 改 |
| 适合 | 有行为的对象 | 小数据 | DTO、查询结果、消息 |

> 阶段 1 里说“先别用 record”，是因为当时还没学；现在可以用了。记账本里用 record 表示“月度汇总”和“分类统计”这种只读结果，很合适。

**扩展方法**：给现有类型“加方法”，不用改原类型、不用继承。三个条件：

1. 类必须是 `static`
2. 方法必须是 `static`
3. 第一个参数前加 `this`，表示“扩展哪个类型”

```csharp
public static class StringExtensions
{
    public static string Truncate(this string value, int maxLength) { ... }
}
```

调用时像实例方法一样：`"abc".Truncate(2)`。注意：

- 扩展方法不能覆盖已有方法（原类型有同名方法时，原方法优先）
- 扩展方法可以“挂在 null 上”调用，但方法体里访问 `value.Length` 会空引用；所以上面先 `string.IsNullOrEmpty` 判断
- 一般放在以 `Extensions` 结尾的静态类里，一个文件放一类扩展

**可空类型**：

- 值类型：`int?` 是 `Nullable<int>` 的简写，可能是 `null`；用 `.HasValue` / `.Value` / `??` 处理
- 引用类型：项目开了 `<Nullable>enable</Nullable>` 后，`string` 表示“不应为 null”，`string?` 表示“可能为 null”
- `?.`：左边为 null 就短路，整个表达式返回 null
- `??`：左边为 null 就用右边的值
- `??=`：左边为 null 才赋值
- `!`：null 包容运算符，告诉编译器“我保证不是 null”；**能不用就不用**，用错了运行时照样空引用

常见警告：

| 警告 | 含义 | 处理 |
|---|---|---|
| `CS8600` | 把可能为 null 的值赋给非空变量 | 变量声明成 `string?`，或先判空 |
| `CS8602` | 解引用可能为 null 的变量 | 用 `?.` 或 `if (x is not null)` |
| `CS8604` | 把可能为 null 的参数传给非空参数 | 调用前判空，或改参数为 `string?` |

这些是**警告不是错误**，程序能跑，但说明你有空引用风险。阶段 3/4 的 Web 项目里，空引用是最常见的 500 错误来源，现在养成习惯。

> 和 JS / TS 对比：JS 只有 `null` / `undefined`，任何变量都可能是空；TS 的 `strictNullChecks` 和 C# 的可空引用类型很像——类型后面加 `?` 表示可能为空，编译器逼你处理。C# 还多了值类型的 `Nullable<T>`（`int?`），这是 JS 没有的。

```csharp
using System.Text.Json.Serialization;
using System.Text.Unicode;

public class TransactionStore
{
    private readonly string _filePath;
    private static readonly JsonSerializerOptions Options = CreateOptions();

    public TransactionStore(string filePath)
    {
        _filePath = filePath;
    }

    private static JsonSerializerOptions CreateOptions()
    {
        var options = new JsonSerializerOptions
        {
            WriteIndented = true,
            PropertyNameCaseInsensitive = true,
            Encoder = JavaScriptEncoder.Create(UnicodeRanges.All)
        };
        options.Converters.Add(new JsonStringEnumConverter());
        return options;
    }

    public async Task<List<Transaction>> LoadAsync()
    {
        if (!File.Exists(_filePath))
        {
            return new List<Transaction>();
        }

        try
        {
            string json = await File.ReadAllTextAsync(_filePath);
            return JsonSerializer.Deserialize<List<Transaction>>(json, Options) ?? new List<Transaction>();
        }
        catch (JsonException)
        {
            string backupPath = _filePath + ".bad";
            File.Copy(_filePath, backupPath, overwrite: true);
            Console.WriteLine($"数据文件格式损坏，已备份到 {backupPath}，本次从空账本开始。");
            return new List<Transaction>();
        }
    }

    public async Task SaveAsync(List<Transaction> transactions)
    {
        string? directory = Path.GetDirectoryName(_filePath);
        if (!string.IsNullOrEmpty(directory))
        {
            Directory.CreateDirectory(directory);
        }

        string json = JsonSerializer.Serialize(transactions, Options);
        await File.WriteAllTextAsync(_filePath, json);
    }
}
```

```csharp
public class Ledger
{
    private readonly List<Transaction> _items = new();

    public int Count => _items.Count;
    public IReadOnlyList<Transaction> Items => _items;

    public void Load(IEnumerable<Transaction> transactions)
    {
        _items.Clear();
        _items.AddRange(transactions);
    }

    public void Add(Transaction transaction)
    {
        _items.Add(transaction);
    }

    public void ListAll()
    {
        if (_items.Count == 0)
        {
            Console.WriteLine("还没有任何记录。");
            return;
        }

        for (int i = 0; i < _items.Count; i++)
        {
            Console.WriteLine($"{i + 1,3}. {_items[i].GetInfo()}");
        }
    }

    public bool Delete(int number)
    {
        int index = number - 1;
        if (index < 0 || index >= _items.Count)
        {
            return false;
        }

        _items.RemoveAt(index);
        return true;
    }

    public bool Update(int number, decimal newAmount, string newNote)
    {
        int index = number - 1;
        if (index < 0 || index >= _items.Count)
        {
            return false;
        }

        _items[index].Amount = newAmount;
        _items[index].Note = newNote;
        return true;
    }

    public void ShowMonthlyStats()
    {
        if (_items.Count == 0)
        {
            Console.WriteLine("还没有任何记录，无法统计。");
            return;
        }

        var monthly = _items
            .GroupBy(t => t.Date.ToString("yyyy-MM"))
            .OrderBy(g => g.Key)
            .Select(g => new MonthlySummary(
                g.Key,
                g.Where(t => t.Type == TransactionType.Income).Sum(t => t.Amount),
                g.Where(t => t.Type == TransactionType.Expense).Sum(t => t.Amount)));

        foreach (var m in monthly)
        {
            Console.WriteLine($"{m.Month} 收入 {m.Income:C} 支出 {m.Expense:C} 结余 {m.Balance:C}");
        }
    }

    public void ShowCategoryStats()
    {
        var expenses = _items.Where(t => t.Type == TransactionType.Expense).ToList();
        if (expenses.Count == 0)
        {
            Console.WriteLine("还没有支出记录，无法统计分类占比。");
            return;
        }

        decimal total = expenses.Sum(t => t.Amount);
        if (total <= 0)
        {
            Console.WriteLine("支出总额为 0，无法计算占比。");
            return;
        }

        var stats = expenses
            .GroupBy(t => t.Category)
            .Select(g => new CategoryStat(g.Key, g.Sum(t => t.Amount), g.Count()))
            .OrderByDescending(s => s.Total)
            .ToList();

        Console.WriteLine($"支出合计：{total:C}");
        foreach (var s in stats)
        {
            decimal percent = s.Total / total * 100;
            Console.WriteLine($"{s.Category,-4} {s.Total,10:C}  {percent,5:F1}%  ({s.Count} 笔)");
        }
    }

    public void ShowLargestExpense()
    {
        var largest = _items
            .Where(t => t.Type == TransactionType.Expense)
            .MaxBy(t => t.Amount);

        if (largest is null)
        {
            Console.WriteLine("还没有支出记录。");
            return;
        }

        Console.WriteLine($"最大单笔支出：{largest.GetInfo()}");
    }
}

public record MonthlySummary(string Month, decimal Income, decimal Expense)
{
    public decimal Balance => Income - Expense;
}

public record CategoryStat(string Category, decimal Total, int Count);
```

## 阶段 2 验收自查（达到后才能进阶段 3）

对照学习计划的验收标准，能用自己的话讲清即可：

1. **泛型解决了什么问题？** —— 一份代码适配多种类型，编译期类型检查，不用 `object` 强转和装箱。`List<T>` 就是泛型。
2. **委托和事件是什么关系？** —— 委托是“方法的类型”，可以存方法、当参数、多播；事件是委托的封装，发布者在类内触发，订阅者只能 `+=` / `-=`。
3. **LINQ 的延迟执行是什么意思？** —— 查询定义时不执行，`foreach` / `ToList()` / `Count()` 枚举时才执行；原集合变了，结果会变。
4. **`First` 和 `FirstOrDefault` 有什么区别？** —— 找不到时 `First` 抛异常，`FirstOrDefault` 返回 `null`（引用类型）或默认值（值类型）。
5. **async/await 解决了什么？** —— 等待 I/O 时不阻塞线程；`Task` ≈ `Promise`，`Task.WhenAll` ≈ `Promise.all`。
6. **JSON 持久化要注意什么？** —— 公共属性、大小写、枚举转字符串、中文编码、`JsonException` 备份。
7. **record 和 class 有什么区别？** —— record 按值相等、自带 `ToString`、用 `with` 复制；class 默认引用相等、可变。
8. **可空类型 `?` 有什么用？** —— 明确“可能没有值”，编译器提醒判空；值类型用 `Nullable<T>`（`int?`）。
